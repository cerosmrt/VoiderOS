# VoiderOS — Permanent context for Claude Code

## What is this

VoiderOS is a personal operating system built on NixOS. Its core is Voider:
a PyQt6 application that acts as a full desktop shell. No panel, no taskbar.
Voider IS the desktop.

The philosophy: `/void` is the single source of truth for all written text.
Code serves the texts, never the other way around.
Direct inspiration: Terry Davis's TempleOS.

The current project state and pending features are in `~/VoiderOS/roadmap/pending.txt`.
What has already been implemented is in `~/VoiderOS/roadmap/implemented.txt`.

├── 0.txt                       ← scratch / active draft

├── I.txt                       ← compiled "I"
├── O/                          ← corpus / readings (symlink to /mnt/data, outside git)

## Development workflow

```
proto-voider/   →   pkgs/voider-py/   →   rebuild
  (sandbox)        (copy files)           (user)
```

1. All new development goes to `proto-voider/`
2. Tests in `proto-voider/tests/` — must pass before promoting
3. Promote = copy files from `proto-voider/` to `pkgs/voider-py/`
4. The rebuild is run by the user, never by the agent

**Launch proto-voider:**
- From desktop: `Super+P`
- The system Voider (`voider-py`) boots automatically at login; proto-voider is the dev sandbox, runs independently alongside it

**Rebuild (user only):**
```bash
sudo nixos-rebuild switch --flake /home/federico/VoiderOS#voider
```

**Tests:**
```bash
cd /home/federico/VoiderOS/proto-voider
pytest tests/ -v
```

## /void — Absolute rules

`/void` contains real writing. A lost text cannot be recovered.

### Before any operation that modifies /void

Mandatory snapshot:
```bash
git -C /home/federico/void add -A I/
git -C /home/federico/void commit -m "snapshot $(date '+%Y-%m-%d %H:%M:%S')"
```
Always use `git -C /home/federico/void` — Voider does not run from that cwd.

### Writing in /void

- Atomic writes only — never write a file partially
- Voider's autosave saves on keypress — there is always a version on disk
- Never rewrite a `.txt` by hand without a prior snapshot

### Multiple instances

Voider can run in multiple simultaneous instances (desktop + detach).
The last-writer-wins problem (one instance overwriting another) is solved with
IPC via QLocalSocket/QLocalServer:

- When an instance saves a file → sends an IPC message to the others
- The others reload that file from disk
- No lock, no restriction — instances sync with each other

## Absolute rules

### 🚫 Never

- Modify, overwrite, or delete any `.txt` in `/void` without a prior snapshot
- Edit `.py` files in proto while Voider has live text open
  (the watcher may restart and overwrite text being edited)
- Run the rebuild — that is done by the user
- Edit `nix/hardware-configuration.nix`
- Manually edit `flake.lock` or `Cargo.lock`
- `git push --force` in `/void`

### ✅ Always

- Read `~/void/pending.txt` at the start of each session to understand current project state and roadmap
- Develop in `proto-voider/` first
- Run tests before promoting to `pkgs/voider-py/`
- Git snapshot before any write to `/void`
- Warn the user before the rebuild (kills Voider and restarts)

### Before implementing anything

1. Summarize in your own words what you are about to do and why, so the user
   can confirm you understood correctly before any questions are asked.
2. Ask all relevant questions one at a time, in multiple choice format when
   there are clear options. Wait for a response before moving to the next.
3. Do not write a single line of code until the user explicitly confirms
   you are on the same page.
4. One task at a time. Do not move to the next backlog item without the user
   explicitly requesting it.

### Development loop

For every new feature:
1. Write the test first
2. Run it — it must fail before you implement (confirms the test is real)
3. Implement until it passes
4. If any test fails after a change, fix it before moving on
Never leave a failing test and continue.
